# 9.0 M4 - where it stands

The record of M4 (`plan/9.0.md`, *M4 - confinement, and a real Windows
AppContainer*) as far as it has got, written so the next session can pick it
up without this one's context. `plan/9.0.md` is the plan; this file records
what was done against it and does not change it. `plan/9.0-m3-progress.md`
is the rung before, which is **done**.

**As of 2026-10-12, second checkpoint (`9.0.0-alpha.12`).** sabline-rt
**confines its own runs**: it derives the budget's policy, asks the
operating system for it in its own process before the program's first
statement, and records the level, the reason, the layers and the policy's
digest in its own receipt. `--confine strict` and `--require-confinement`
are answered there, so neither keeps a run in the package any more, and the
command that starts sabline-rt holds **itself** to the same policy, because
a relayed call to the network, a granted Python module or a tool is made
there. The gate is green over 41,939 comparisons; `check_confine.py` is
124/0 and `check_confine.py --runtime rust` is 74/0, on Windows.
**sabline-rt does not enter a Windows AppContainer yet**, so Windows holds
neither reads nor the network - in its own words, which are not the
package's, because the reason is not the package's.

## What is done

### The first checkpoint's (2026-10-12, no pre-release)

- **M3 closed**, the native engine held to the interpreter, `fuzz_native.py`
  comparing stderr, a function value checked once, sabline-spec 0.16.0, the
  AppContainer spike, `--confine strict` and `--require-confinement` (E326)
  in the Python runtime at every entry point, with the escape cases in
  `check_confine.py`. The git history of #154 is the detail.

### This checkpoint's (`9.0.0-alpha.12`)

- **`os_policy` in Rust** (`rt/.../confine.rs`): the same derivation, pure,
  with `FFI_WIDENS` module for module, `restricted`, `why_not_enforced`,
  `policy_sha256` and the `strict` rule. The agreement gate compares, for
  every one of its 2,975 budgets, the policy, its digest, what it asks the
  system to hold and why it asks for nothing - **under `--confine strict`,
  without it and under `--no-confine`** - as a new row, *the OS policies*.
- **The confinement tables compared on every platform**, as a second new
  row: `FFI_WIDENS` module for module, and for 18 fixed budgets × 2 modes
  the **seccomp filter** for both machines, the **Landlock masks** for ABI 1
  to 4, and the **macOS profile**. None of it is behaviour and all of it is
  what the kernel is asked for, so a system call number or an access bit
  typed wrong in one runtime is a difference on the commit that types it -
  found on Windows, where no layer of the three is ever applied.
  `sabline/confine.py`'s `mac_profile` takes `home`, `cwd` and
  `interpreter` for this, and `landlock_masks` is the four fields of a plan
  that are not the machine's.
- **The layers**, each in its own module, each the package's ported:
  `confine_linux.rs` (Landlock, every access bit, the ruleset, the port
  rules; seccomp-bpf, both syscall tables, the whole filter),
  `confine_macos.rs` (`sandbox_init` and the profile),
  `confine_windows.rs` (the job object, every privilege but
  `SeChangeNotifyPrivilege` removed, the low integrity level and the label
  for a private temporary directory).
- **Every thread of the process is held.** Landlock holds the thread that
  enters a ruleset and the threads it starts afterwards, never a sibling, so
  `sabline-rt exec` was restructured: this thread reads the request and
  starts the run's thread; the run's thread reads, checks and asks for the
  policy; asking reaches back through `confine::other_threads_hold_themselves`
  and the frame-writing thread enters the same ruleset and says whether it
  did, which the run counts before it decides its level; and only then is
  the thread that reads the answers started, as a child of a held thread. A
  thread left over is a gap in the reason and the level is never `full`.
- **The fault-injection hook ported** (`confine_fault.rs`,
  `SABLINE_FAULT_INJECT`): read, write, connect, spawn, spawn-breakaway,
  signal, mount, unix-socket, with the package's words, E319 under
  confinement and a line on the error channel without it.
- **Both options in sabline-rt**: the request carries `confine`,
  `require_confinement`, `confine_reads`, `confine_writes`, `confine_temp`,
  `confine_read_any` and `host_confinement`; E326 is raised before the first
  statement and is in `REFUSAL_CODES` in both runtimes now. `KEPT`'s
  `confinement` reason and its notice are **gone**.
- **The confined host, for a command** (item 7, done early because
  `--confine strict` would otherwise hold the runtime and not the module):
  `confine.confine_the_host(budget)` applies the policy to the command's own
  process *after* sabline-rt has been started, since the policy lets no
  process be started, and the request says what level it got. A pool's host
  is its worker, confined already. An unbounded `sabline.run()`'s host is
  the caller's process, which EXEMPT says Sabline never confines, so a run
  there whose budget grants `net`, `ffi` or `tool` carries
  `confine::relayed_elsewhere`'s sentence in its reason and is `partial`.
- **`check_confine.py --runtime rust`**: every child is started with
  `SABLINE_REFERENCE_RUNTIME=rust`, so the honesty test, what still works,
  what is reported, what a program cannot reach, what is tried against the
  confinement itself and both options are asked of sabline-rt. 74 passed, 0
  broken on Windows. Three parts stay the package's and say so: the policy,
  the filter and the table (the gate compares those); the escape targets
  (measured on a Sabline whose *Python* checks are knocked out); and
  `sabline eval`.
- **The `confine-rt` CI legs**: a matrix of ubuntu, windows and macos
  running `check_confine.py --runtime rust` and then the package's, with the
  kernel's Landlock ABI printed on Linux.
- **`unsafe`, for the first time, in four modules and nowhere else.** The
  workspace denies rather than forbids it (forbid cannot be lifted), the
  four lift it with the reason in their own module comments, and
  `check_rt.py` holds that list - `MAY_BE_UNSAFE` - in both directions: a
  fifth file is a failure, and a listed file that no longer lifts it is one
  too. Every block carries a `// SAFETY:` comment naming a test that exists.
  `rt/README.md`'s section is rewritten; the scan has a fifth fixture.
- **The documents**: docs/confinement.md's new section, *sabline-rt confines
  its own runs*; the CHANGELOG's `api:` line and the alpha.12 entry; this
  file and `plan/9.0.md`'s M4 section.

## The maintainer's three answers of 2026-10-12, and what was done with them

1. **A loopback host inside an AppContainer** - (a): the container is left
   off for a budget granting a loopback host, and the level's reason says
   so. **Not written yet**, because there is no container yet; it is the
   first thing the container's code does, and the condition is recorded in
   `rt/spikes/appcontainer/README.md`. Note for whoever writes it: while the
   network is relayed to the host, a `net:localhost` budget works *inside* a
   container, so leaving it off is a loss until sabline-rt opens its own
   connections. Written as decided, it is conservative and never a false
   claim.
2. **A killed run's ACE** - (a): the parent takes it back, with a
   best-effort sweep of profiles that no longer exist at the next run's
   start. **Not written yet**: the same code.
3. **`--confine strict` as the default** - no, as 0006 says. Recorded here
   so the question is not re-asked each rung.

## What is next, in order

1. **The Windows AppContainer.** The spike is the measurement and
   `rt/spikes/appcontainer/src/main.rs` has every call. The design this
   checkpoint's code is shaped for: `sabline-rt exec`, asked for
   confinement on Windows, reads the request, **loads the program to learn
   which files it reads** (a lookahead, never an answer - the child's load
   is what refuses anything), creates a profile named for the run, grants
   one ACE per file and per granted directory, starts a child
   `sabline-rt exec` inside the container with the job object and its own
   standard output and error inherited, pumps the one line of the request
   and then the rest of standard input into it, waits, removes every ACE and
   deletes the profile. Then answers 1 and 2 above, the `ENFORCES` rows, and
   THREAT_MODEL.md's Windows row - whose page is **2,747 bytes from the
   budget**, so the rule is to split the page, never to raise the budget or
   trim the text.
2. **`ENFORCES` in sabline-rt, row for row**, which lands with the
   AppContainer: until the Windows rows differ, a second copy of the same
   prose is two places to keep one fact. The mechanism to use is
   `check_confine.py`'s `table_cases`, which already holds THREAT_MODEL.md
   to `confine.ENFORCES` row for row; give the Rust table a held/not-held
   flag per platform and require Rust's ≥ Python's, with the cells that
   differ listed with a reason.
3. **`sabline eval` through sabline-rt**, which is `KEPT`'s last reason
   besides `sabline trace`, and with it `check_receipts.py`'s three replays
   and `check_library.py`'s producer-version question.
4. **The doors' own command lines**: `sabline serve` and `sabline mcp` take
   `--no-confine` and not yet the two options; a `PoolRegistry` made with
   either already carries it to every pool, so this is the operator's flag
   and nothing deeper. `sabline eval` refuses both by name, as it refuses
   `--no-confine`.
5. **A CI leg on a kernel without Landlock**, which the plan asks for and
   this checkpoint did not add: a GitHub runner has one, and there is no
   honest way to take it away (a variable that turned a layer off would be
   a variable that turns confinement off, which `check_self_budget.py`
   exists to refuse). The Rust unit tests answer the `abi == 0` path and
   `apply` reports `no: this kernel has no Landlock`; what is missing is a
   machine that proves it. A container with `seccomp=unconfined` and an old
   kernel, or a self-hosted runner, is the only way seen so far.

## Questions for the maintainer

1. **Is `partial` the right answer for an unbounded `sabline.run()` whose
   budget grants `net`, `ffi` or `tool` through sabline-rt?** Its host is
   the caller's process, which Sabline must never confine, so the call is
   made somewhere this policy does not reach and the receipt says so. The
   alternatives are (a) as it is - `partial`, with the sentence in the
   reason; (b) keep such a run in the package, which confines nothing either
   but at least makes the module's code run where the budget's checks run;
   (c) refuse it. Recommended: (a), which is what shipped.
2. **Should the four `unsafe` modules be three?** `confine_fault.rs` needs
   it for exactly three calls - a Unix socket made, `kill(pid, 0)`, a bind
   mount - and all three are the honesty test's attempts and not the
   confinement itself. Leaving them there keeps the hook in one file; moving
   them into `confine_linux.rs` and `confine_macos.rs` would make the list
   three and the hook two files. Recommended: four, as it is.
3. **The no-Landlock leg** (*What is next* 5): is a self-hosted runner worth
   it, or is the unit test and the reported reason enough? Recommended: not
   worth a runner; say in THREAT_MODEL.md that the no-Landlock path is
   tested by unit test and not by a machine.

## Traps met in this session

- **A patch script's own line continuation eats a Rust one.** Writing
  `"...gave \` + newline + indent inside a *Python* triple-quoted string
  makes Python join the lines and keep the indent, so the Rust literal ends
  up with fourteen spaces in the middle of a sentence - which compiles, runs
  and reads wrong. Four strings in `confine.rs` shipped like that for an
  hour. `check_confine.py` had two lines damaged the same way since #154.
  **Write a patch script's replacement text as a raw string (`r'''...'''`),
  or write the file with the Write tool.** The old trap - heredocs halve
  backslashes - is the same trap one layer up.
- **A confinement that is settled must say so, on every platform.** The
  thread that writes the frames waited to be asked to hold itself; only
  Landlock asks, so on Windows and macOS it waited for ever and a run that
  relayed a call deadlocked. The fix is one notification from the one place
  that knows (`confine::now_settled`), not a platform test at the far end.
  A `hello` with no relayed call passed throughout, which is why it took a
  traceback to find: **when a run through sabline-rt hangs, dump the host's
  stack first - it says which side is waiting.**
- **A static holding a channel's sender keeps that channel open.** The
  frame-writing thread waited on `recv()` and used "the sender dropped" as
  "the run ended"; a clone of the sender lived in the hook's static, so the
  channel never closed and a request with no `path` hung for 300 seconds.
  Send the end explicitly instead of inferring it from a drop.
- **rustfmt will move an `unsafe` away from its `// SAFETY:` comment** when
  the line it is on grows too long, and `check_rt.py` then says the comment
  is missing. Put the comment *inside* a block whose only content is the
  call (`let x = { // SAFETY: ... \n unsafe { ... } };`).
- **A Windows build will not relink while a stray `sabline-rt.exe` runs.**
  A test that timed out left one; `cargo build` then fails with *Access is
  denied* and nothing says why. `Get-Process -Name sabline-rt | Stop-Process
  -Force`.
- The earlier traps stand: a notice on stderr is a difference in every suite
  that compares it; one folder for both runtimes, remade for each; read a
  failure's message before believing the claim it is about.
