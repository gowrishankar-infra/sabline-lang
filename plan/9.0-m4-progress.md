AppContainer*) as far as it has got, written so the next session can pick it
up without this one's context. `plan/9.0.md` is the plan; this file records
what was done against it and does not change it. `plan/9.0-m3-progress.md`
is the rung before, which is **done**.

**succeeded**, so M4's Windows half goes ahead as planned. The Python
runtime's halves of `--confine strict` and of refusing a run under weak
confinement landed first, as decisions/0006 asks, each with escape tests.

sabline-rt asks the operating system for nothing, its receipt says so, and a
run asked for either option stays the Python package's and says so. **No
pre-release**: the crate did not change, and a pre-release ships the crate

## Questions for the maintainer

1. **The loopback address is unreachable from inside an AppContainer**, even
   with `internetClient`: when sabline-rt makes its own connections, a
   granted `net:localhost` cannot be reached from inside a container - (a)
   leave the container off for a budget that grants a loopback host, saying
   so in the level's reason; (b) keep the container and let the connection
   fail at the call; (c) ask an administrator to exempt the container, which
   Sabline cannot do for them. Recommended: (a).
2. **Who takes back an ACE a killed run left on a user's directory?** (a)
   the parent that granted it, with a best-effort sweep of profiles that no
   longer exist at the next run's start; (b) nobody, and the profile name is
   per-run so the SID is dead, which is documented as what it is.
   Recommended: (a).
3. **Should `--confine strict` become the default in 9.0?** 0006 says making
   it so is a breaking change and belongs with 0005's set if at all, and it
   is not proposed. It would make a granted `ffi` module's reach the budget's
   rather than the module's, and break a program whose module does I/O the
   budget does not grant. Recommended: no, as 0006 says - but the question
   is worth answering once rather than re-asked each rung.
4. **The port stopped before it began, and not for a reason in this
   repository**: the session planning it had a reply cut short by a safety
   stop on the tool side while reading the confinement code, twice, and the
   maintainer chose a checkpoint over pressing on. Nothing here is blocked by
   it; it is recorded because the next session will wonder why a rung that
   starts with a spike has no Rust in it.

## Traps met in this session

- **A suite's own harness can fail the thing it tests**: two cases here
  failed on Linux for reasons in the case, not the code - a receipt read
  before the run that would write it had ended, and a Pool with no
  `import_root`, which holds no reads on Linux and so can never be `full`.
  Read a failure's message before believing the claim it is about.
- **`sabline.run` with no limit can never be confined**, so a level asked of
  it is always refused; a test that wants a level needs a limit or a pool.
- The earlier traps stand: heredocs halve backslashes - write patch scripts
  with the Write tool; a notice on stderr is a difference in every suite that
  compares it; one folder for both runtimes, remade for each.
