What the operating system enforces

This is the what the operating system enforces section of the threat model, on a page of its own so that neither page outgrows the size a page of the site may be, as known-open.md is. The threat model says what Sabline defends against; this page says, item by item, how much of that the kernel holds too, on each of the three systems and in each of the two runtimes.

From 8.4 the process that runs a program asks the operating system to hold the budget it was given, before the program's first statement runs, so that a fault in Sabline itself is a crash inside a box and not an escape. The derivation is one function, os_policy in sabline/confine.py: budget in, OS policy out, reading nothing of the machine. This table is that module's ENFORCES, and check_confine.py fails when the two differ.

Through sabline-rt, which enters a container Windows' Python cannot #

The table above is the Python package's own runtime. From 9.0 a run may go through sabline-rt (SABLINE_REFERENCE_RUNTIME=rust), whose own process is the run's - so it can be started inside a Windows AppContainer, where a running python.exe cannot enter one and a fresh one started in one cannot read its own installation. Everything else is the same table: sabline-rt os-policy --enforces writes how much of each row above that runtime's kernel holds, and check_confine.py holds it to be at least the package's everywhere, with a reason on every cell that differs. These are all of them.

Budget itemSystemThe packageThrough sabline-rtWhy it differs
no fs grantedwindowspartlyyeswindows: the run's own process is started inside an AppContainer with an ACE for nothing but the files it reads, so a read or a write of anything of the user's is refused by the kernel and not only a write
fs:read:DIRwindowsnoyeswindows: the container is given one ACE for DIR, resolved, and one for each file the run itself reads; a read of anything else of the user's is refused
fs:write:DIRwindowsnoyeswindows: the container is given an ACE for DIR that carries write and delete, and the integrity level is not lowered, because the ACE is what holds the write
no net grantedwindowsnoyeswindows: the container is made with no capability, so a socket to anything outside the machine is refused with WSAEACCES
net:HOST, net:HOST:PORTwindowsnopartlywindows: the container is made with internetClient, which admits every host, so the host is held by the language alone, as on Linux and macOS
ffi:MODULE under --confine strictwindowspartlyyeswindows: under strict the policy is the budget's own grants, and the container holds a module's own calls - native code, ctypes - as it holds the runtime's

A container is left off for a run whose budget it would refuse something the budget allows, and the receipt's confinement_reason says which: a budget granting a loopback host, since Windows isolates a container from the loopback address unless an administrator exempts it; and a budget that restricts neither reads nor writes, since a container reaches only what it is given an ACE for. Such a run gets the table above, as it did before 9.0. A budget that grants any host keeps its container: it does not say it needs the loopback address, which is then the one address the run itself cannot reach - its own network calls are made by the process that started it, which can.

What the interpreter itself must read is allowed beside the grants, on Linux by name: Python's own installation and every directory it imports from, the sabline package and the standard library beside it, the system's shared libraries, /dev/null, /dev/urandom and the /proc and /sys entries Python asks for, the time zone data, the files the program was read from, a private temporary directory - and, under a net grant only, the resolver's configuration and the TLS roots. @N counts stay in the language.

A granted ffi module widens the OS policy to what that module needs, named per module (FFI_WIDENS). A module that is not in this table widens to nothing enforced - what it needs is not known, and a run that worked before 8.4 is not refused - and the audit's confinement.widened_by names every module that widened the policy and to what.
