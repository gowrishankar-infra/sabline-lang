# 9.0 M3 - where it stands

The record of M3 (`plan/9.0.md`, *M3 - the interpreter, the budget,
`Secret` and receipts*) as far as it has got, written so that the next
session can pick it up without this one's context. `plan/9.0.md` is the
plan; this file records what was done against it and does not change it.
`plan/9.0-m2-progress.md` is the record of the rung before.

**As of 2026-10-09, second checkpoint.** sabline-rt runs a program under
any budget short of the network, Python and a tool, and the agreement gate
runs every program written for a budget under its own. It is pre-release
**`9.0.0-alpha.7 - M3: the builtins under every budget, as far as they
got`**: `rt/Cargo.toml` says that version, and release.yml tags it and
publishes the crate when the merge commit's tests pass. Nobody tags by
hand. (alpha.6, the first checkpoint, was published by release.yml on
2026-10-09: the tag `v9.0.0-alpha.6`, the crate, a GitHub pre-release.)

**M3's exit criteria are not met, and none is claimed.** What is not done
is listed below, in the order to do it; receipts are first.

## The maintainer's decisions of 2026-10-09, and what was done with them

The first checkpoint left three questions; the answers are recorded in
`plan/9.0.md`'s M3 section (*Decided on 2026-10-09*), and each is done.

1. **A counted size limit stops a compared run that grows without bound**,
   like the step limit; never wall-clock time or real memory; the stop is
   in the run document; the memory-cap program joins the gate; the real
   cap stays the operating system's (M4). Done: `run_dump.SIZE` =
   4,194,304, `state._SIZE_LIMIT` / `_SIZE_MADE`, `runtime.size_of` and
   `made`, and `Runtime::with_size_limit` / `interp::size_of` in the crate.
   What makes a value, and so is counted: a `+` that makes a text or a list;
   a list or map literal; every builtin's answer but `get`, `get_or` and
   `declassify` (`HANDS_BACK`) and `to_text` of a text; the text `print` and
   `log` write and `ask` asks with, before it is written. A text counts its
   UTF-8 bytes (a lone surrogate three), a list or map its items. Stopped at
   the operation whose count passes the limit (`>`, not `>=`). The largest
   any ending program in the corpora makes is 100,000 (a printed 100k-
   character literal), so the limit has a 40x margin. The run document is
   version 2, with `stopped_by`. `RUN_EXCLUDED` is empty: E611's program is
   stopped at its eighteenth doubling, in both. The benchmark's five
   programs that grew forever are now stopped by size, which took the
   gate's run from 2m19s to 1m45s here.
2. **A function value prints as `fn` and its name** - declared, or the
   lifted `fn#N` - in both runtimes, everywhere a value is written: `print`,
   `to_text`, `format`, `+`, a broken promise's message, inside lists, maps
   and records. Done: `Function.__repr__` (sabline/nodes.py) and `Bound`
   moved to `sabline/values.py` with a `repr`; `value.rs`'s `write_repr`.
   SPEC.md 12a says it; the CHANGELOG carries the compatibility line.
3. **The E402 defect is fixed**, both loaders in one commit:
   `loader.qualify` renames the `Closure` as well as the lifted function
   (`Expr::Closure` in `loader.rs`). `parser.lifted(name)` / `show::lifted`
   make `lib.fn#N` read as "this function value"; `library.py`'s audit,
   `editor.py` and `ratchet.py` use it. SPEC.md 10 says it. Tests:
   `tests/unit/test_loader.py` `NamedFunctionValues`, `rt/.../tests/runs.rs`,
   and `agreement_checks.TREES` (two more trees, named and flat). **The
   adversarial pass**: thirteen libraries, each imported flat and under a
   name, through both run-dumps (values carrying names, nested, handed back
   and called, passed back in, calling the library's own functions by name,
   looping, failing inside `check`, a local named like a function, a broken
   promise, recursion through `all_of`, printing the value), plus the
   prover (`check --strict`), native code and `sabline audit` on the named
   ones. Every pair agreed flat-against-named and Python-against-Rust. It
   found the `all_of` defect below, and the library-promise attribution
   (*Questions*, 2).

## The two chores

- **`check_release.py`'s timing checks** (the one at 2753 and its two
  siblings): `consistent` and `published --require` under `--timeout 0.3`
  now run on `CountedClock`, a clock that moves only when slept on, swapped
  in for `release_checks.time` by `counted_clock()`. Six polls on every
  runner, asserted exactly; nothing waived.
- **The stale-sitemap rule no longer depends on the UTC day of a merge.**
  `build_docs.py` dates each page by a digest of its sources' git blob ids
  (`source_digests`, `git ls-files` + `git hash-object` for the working
  tree, `git ls-tree` for a commit), kept with its date in
  `docs/sitemap-dates.json` (one address a line, so two PRs merge); a digest
  not seen before is dated today. `check_site.py`'s STALE asks of HEAD alone
  whether every page's sources digest to what the committed record says and
  the sitemap gives the record's date - so it runs on a shallow clone, and
  site.yml's `fetch-depth: 0` and check_workflows' rule for it are gone.
  It also ends the Windows autocrlf trap: blob ids are of the normalised
  content, so a stat-dirty file no longer bumps its page. The record lives
  in `docs/` (served, harmless) because release.yml's `move_pins` job
  stages `README.md EMBEDDING.md docs` and refuses anything else - with it
  in `site/` the release harness went red, which is how that was found.

## What is not done, in the order to do it

1. **The recorder and `sabline.receipt/1`**, field for field after
   plan/9.0.md's normalised list (`producer.*`, `startedAt`,
   `wall_time_ms`, `<source>` names, the confinement fields by rule).
   `Runtime::grant_uses` already counts what `_grant_used` counts; the
   recorder's `note`s for `declassify` (with the reason) and the HMACs
   (`key_fingerprint`, `FINGERPRINTS_PER_SITE`, "many") are not written
   yet - `sabline/recorder.py` and `runtime.run_digest` are the reference.
   Then a receipt document in the gate, the way the run document is.
2. **The audit stream** (decisions/0007, 32b): the receipt's fields as they
   are produced, one JSON object per line; 2 days in Python, 2 in the port.
3. **A run target for the differential fuzzer** (`fuzz_agreement.py`):
   the size limit answers what held it. It must not write a program that
   makes one value far larger than the limit in one operation - the
   residual below.
4. **`sabline run` and `sabline.run` through sabline-rt** (decisions/0002),
   which is what lets the suites of the fourth criterion be asked of it.
5. **The network, Python and tools**, each with a design question: the
   network needs a stand-in server in the gate (conform.py's two) and
   `urllib`'s URL parsing, redirects and proxy refusal (E317) copied;
   `py` needs a decision about what a second runtime does with a Python
   host at all; a tool needs the runner's session.
6. **The organisation ceiling file** (0007, 32c), Python first.
7. **Performance**, M8's: unchanged from the first checkpoint.

**A known residual of the size limit**: a value is counted when it is made,
so one operation can still make a text far past the limit from a container
holding one large text many times (`to_text` of a list of a thousand
references to a megabyte). Nothing in the corpora does; a generated program
could. If one does, the gate fails loudly ("ended ... for the whole batch",
or `raised: MemoryError`), never quietly.

## Questions for the maintainer

1. **Should a file that is not UTF-8 be a failure a program can handle?**
   `read_file` of one raises `UnicodeDecodeError` out of the run - the
   command line prints a Python traceback, and `check read_file(...)` cannot
   catch it; `write_file` of a text holding a lone surrogate does the same
   with `UnicodeEncodeError`, after the file was emptied. Both runtimes copy
   it (`raised` in the run document), so the gate agrees. Recommended: a
   failure, as 8.2 made a NUL in a path one - `cannot read file 'x': it is
   not UTF-8 text` - in both runtimes in one commit, with a CHANGELOG
   compatibility line.
2. **Should a library function's broken `requires` name the library's
   file?** It names the importer's file with the library's line, because
   the promise is checked before the callee's body and is blamed by the
   caller's frame (`call_function`). The prover's E701 does the same.
   Flat or named alike; both runtimes copy it. Recommended: blame the
   callee's `src_file` for E600 at entry.
