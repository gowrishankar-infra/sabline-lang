## The maintainer's decisions of 2026-10-10, and what was done

The third checkpoint left two questions; the answers are recorded in
`plan/9.0.md`'s M3 section (*Decided on 2026-10-10*), and each is done,
both runtimes in one commit.

1. **The reference says one thing on every CPython - 3.12's words - in all
   three places** (commit `5866480` on the branch). `values.read_json`
   reads every JSON document a program hands the reference (the `json_`
   builtins, `py`'s arguments, `request`'s headers) and gives 3.13's
   "Illegal trailing comma before end of array/object" as 3.12's
   "Expecting value" / "Expecting property name enclosed in double quotes",
   at the bracket after the white space, where 3.13 names the comma.
   `values.whole_number` refuses past 4,300 digits in 3.12's words
   ("(4300 digits)") before `int()` is asked, wherever the reference reads
   a whole number from text it was given: a JSON number (only through
   `parse_int`, and only for a document longer than 4,300 characters, so
   every shorter one keeps CPython's fast path) and a budget's `@count`
   and `:port` (four places in `budget.py`). `runtime._BASE64` takes only
   whole groups of four, the last padded as the encoder pads it - what
   3.12's strict decoder takes - so 3.10 refuses `"YWJj=="` and `"="` too.
   sabline-rt already copied 3.12 in all three; only its notes changed.
   **Verified by brute force**: 597,871 base64 texts (every string of up to
   six of `AQg+/=* \n`) and 300,010 random JSON texts give one digest on
   3.10.20, 3.12.13, 3.13.5 and 3.13.13, equal to raw 3.12's
   (`verify_split.py` was a scratch script; the gate and
   `OneAnswerOnEveryCPython` hold it now). The gate's corpora hold what they
   left out: five base64 texts in `agreement_runs.TEXTS`, the edge
   `json-a-trailing-comma-and-a-long-number` (twenty documents), and eight
   budgets past 4,300 digits in `agreement_budgets.EDGES`; `fuzz_parsers`'
   `reference_split` and its counting are gone. SPEC.md 10 says what
   `base64_decode` takes; the CHANGELOG carries the compatibility line.
2. **The size limit counts what a value writes out before writing it**
   (commit `da953e8`). `runtime.ahead(size, line)` asks, before an
   operation makes what it writes out, whether that would pass the limit,
   and stops the run there - for `to_text` of what is not a text, `print`,
   `log`, `format` (after its E406), a `+` that makes a text or a list,
   `json_of` (before `plain()` copies anything), the three encoders, and
   the message of a broken `requires` / `ensures` (E600, E601) or loop
   invariant (E704), which names values. Nothing is counted there: `made()`
   still counts what is then made, which is exactly those bytes, so a run
   stops at the operation where counting after would have stopped it. The
   reference's walks are `values.written_size` (to_text, and with
   `log=True` what `log_line` makes of it), `shown_size` (`str()`, how a
   promise names a value: `repr` inside containers), `json_size` (plain's
   key collapse included) and `log_size`, each iterative and stopping once
   past its room; `WrittenOutIsCountedFirst` holds each to its writer over
   4,500 generated values, and that each says "past" exactly when the
   writer's bytes are. sabline-rt's are its writers themselves:
   `value::write_text` / `write_str` / `write_repr` write to a
   `text::Sink` - a `TextBuf`, or a `Measure` that counts UTF-8 (or log)
   bytes and is full past its room - and `pyjson::dump_into` to a
   `JsonOut`, so what it counts is what it would write, by construction.
   **The nested-list test** in both: `test_a_list_nested_two_of_the_one_
   below_is_never_made` and `tests/runs.rs`'s `what_is_written_out_is_
   counted_before_it_is_made` - forty levels, eighty-two items, 2^40
   copies of "ha" written out, stopped at each of seven operations and a
   promise. The gate holds `agreement_runs.LAUGHS` (eleven) and
   `room_cases()` (220: each of thirteen writers after making exactly
   SIZE - room, for rooms eight under to eight over what it writes - a
   sweep that straddles each boundary, checked by hand when written).
   `check_gate.py` gains two injections only those see. The fuzzer's
   `RunGen` is gone (CheckerGen prints a `List of Text` again), its
   `size` of 2^18 is gone (the gate's 2^22 applies), and a `MemoryError` is
   a finding: 8,515 runs in five minutes, none.

## What this checkpoint did besides

1. **`sabline run` and `sabline.run` through sabline-rt** (commit
   `5f62871`). The selector is the variable MAINTENANCE.md reserved for
   9.0, `SABLINE_REFERENCE_RUNTIME`: `rust` routes, unset or `python`
   doesn't, anything else is refused (exit 2; `RuntimeChoiceError`, a
   `ValueError`). Chosen because plan/9.0.md already names it as the
   selector ("`SABLINE_REFERENCE_RUNTIME=python` keeps selecting it"; M7
   flips its default) and because `sabline.run` cannot take a `runtime=`
   without changing `tests/api/golden.json`, which M7 requires unchanged.
   *The maintainer can overrule this; nothing else depends on the name.*
   - **`sabline-rt exec --install-dir DIR`** (`src/exec.rs`, the binary's
     `exec`): a JSON request on stdin (path, allow, deny, seed,
     freeze_time, max_read, args, name, source, stream), then JSON frames
     on stdout as the run goes - `{"out"}`, `{"err"}`, `{"read":"line"}`
     and `{"ask": prompt}` answered by `{"line": text|null}`, `{"event"}`
     - and last `{"end": {"document", "receipt"}}`. No step or size limit.
     `Io::relayed` / `Relay` and `Recorder.live` carry frames as *lines*
     (`String`), because `Text` is `Rc` and cannot cross to the writer
     thread. `run_dump::run_relayed`, `Given` gains `args`, `name`,
     `relayed`, `stream`, `source`. The loader takes the entry's text
     (`load_program_given`, as Python's `entry_source`). A parent that goes
     away: the stdin thread sees the end while the run is going and exits
     3 (`ORPHANED`); before the request is read, the end is only the end.
     `tests/exec.rs` drives it.
   - **`sabline/through_rt.py`**: `chosen()`, `binary()` (this checkout's
     build, else PATH), `not_ported(funcs, budget)`, `run(...)`.
     **Command line** (`cli._cli_run_through_rt`, from
     `_cli_run_receipt_or_not`): load, check, prove as `_cli_run` does; any
     problem, or a not-ported effect, returns None and the package's path
     runs as before. Output through `sys.stdout.write`, logs through
     `sys.stderr.write`, `read_line` from `sys.stdin.readline`, `ask` by
     calling `input(prompt)` itself; `--receipt` / `--audit-stream` write
     sabline-rt's. **Library** (`library._run_through_rt`, from `run()`'s
     unbounded path only): output and logs into StringIOs, `stdin=` as a
     StringIO, `ask` as `input()` behaves with a StringIO stdin, the
     stream handed to `audit_stream=` as it comes.
   - **What stays the package's**, each by design until decided or built:
     a program the checks or the prover refuse (nothing runs); a budget
     granting net, ffi or tool to a program a function of which uses it
     (one line on stderr - *the question below*); `timeout=` /
     `max_memory_mb=` runs and the Pool (their worker is confined at its
     first statement, 8.4, and its job object refuses `CreateProcess` -
     "Not enough quota" - so the *caller* must start sabline-rt under the
     limits: the next step); `import_root` (sabline-rt's loader has no E515
     yet); a source that is not UTF-8. Confinement: none, and the receipt
     says so ("nothing was asked of the operating system"); no notice on
     stderr - an earlier draft printed one per run and it made every suite
     comparing stderr fail for a reason that is not in the run.
   - **`check_through_rt.py`**: 325 programs (the run corpus less LAUGHS
     and room cases, and examples/, that end within the run document's
     limits) through both entry points, the variable unset and `rust`,
     compared - output bytes, status, stderr, receipt and stream by the
     gate's `_normalised` and confinement rule, `RunResult` field for
     field - with the command line under `--no-confine` so confinement is
     `none` on both sides. A program the checks refuse must stay the
     package's (stderr not compared: z3's counterexamples vary run to run).
     **0 differences.** ~3 minutes here. In CI's agreement job.

## Questions for the maintainer

1. **What does a run through sabline-rt do under a budget granting the
   network, Python or a tool to a program that uses it?** sabline-rt does
   not do their work yet (item 5). Today, the interim this checkpoint
   built, the run is the Python package's and says so, once, on the error
   channel ("sabline: this run is the Python package's, not sabline-rt's:
   its budget grants the network, which sabline-rt does not do yet
   (SABLINE_REFERENCE_RUNTIME=rust)"); its receipt's producer is
   `sabline-lang`, which is the honest record. "Uses it" is static: a
   function of the program declares the effect (E300 keeps a program from
   reaching an undeclared one), so `--allow all` on a program that never
   touches the network still goes through sabline-rt. The choices:
   (a) **keep the fallback**, notice and all, until each effect is ported -
   a user who asked for sabline-rt always gets a run, and the receipt says
   which runtime made it; (b) **refuse the run before it starts**, a coded
   error naming the effect - sabline-rt or nothing; (c) **run it in
   sabline-rt** and stop with a coded error at the first call it cannot
   make - which is a run that behaves differently from the package's
   halfway through. Recommended: (a) until M7 flips the default, and by
   then the three are ported or the default does not flip for them; (c)
   is the worst of the three, since a program's behaviour would depend on
   which line it reached. Nothing else in M3 waits on the answer.

(Two choices this checkpoint made that the maintainer may want to
overrule, neither of them blocking: the selector is
`SABLINE_REFERENCE_RUNTIME`, and a run through sabline-rt says nothing on
stderr about not being confined - its receipt does.)

## Traps met in this session

- **A module-level dict in the package fails `check_pool.py`** - its scan
  of module-level mutables. Decision 1's `_TRAILING_COMMA` was one, and
  only the suites asked through sabline-rt found it (it fails without the
  variable too). Pairs, or a constant the scan lists.
- **`Text` is `Rc`**: nothing holding one crosses a thread - not a frame,
  not a parsed request (`Given.args`). Send lines; parse on the run's own
  thread.
- **A confined worker cannot start a process** (Windows: the job object's
  "Not enough quota"; Linux: seccomp). Anything that wants sabline-rt from
  inside a pool worker has to be done by the caller instead.
- **A notice on stderr is a difference in every suite** that compares the
  error channel. The receipt is where a run says what it was.
- **`cargo fmt` writes LF** into files the Windows checkout holds as CRLF;
  git normalises, so it shows only as warnings. Patch scripts that keep a
  file's own line ends (`crlf = b"\r\n" in raw`) avoid the churn in Python
  files.
- **Heredoc patches into CRLF files** silently match nothing; use the
  Edit tool or a script that normalises before matching.
- **Rebuilding sabline-rt while a long job spawns it** replaces the binary
  under it; wait, or build into another target dir.
- **`Parser.lambda_n` is process state** the gate never saw, because every
  dump resets it; anything printing `fn#N` from a long-lived process did.

## Found on the way

1. **A function value written inline printed a name that depended on the
   process** (fixed in the reference): `Parser.lambda_n`, a class
   attribute, was reset by the AST, check and run dumps and by nothing
   else, so `sabline.run` called twice in one process printed `fn fn#1`
   then `fn fn#4`, and a pool worker or a door printed whatever the count
   had reached - against the second checkpoint's decision that a function
   value prints as a fixed name. `check_through_rt.py` found it (four
   programs: the library's `fn#21` against sabline-rt's `fn#1`).
   `load_program` resets it, so every program counts from 1, as
   sabline-rt's per-load counter does; `test_the_count_starts_at_one_in_
   every_program`; a CHANGELOG compatibility line.
2. **`values._TRAILING_COMMA` as a dict failed `check_pool.py`** (fixed
   before it reached main; decision 1's own commit has it, the routing
   commit fixes it).
3. **sabline-rt has no "nested too deeply to print"**: the reference turns
   a value nested past Python's recursion limit into E609 when it writes it
   out; sabline-rt's writers recurse on a 128 MB stack and would print it,
   or overflow. No corpus reaches it (the fuzzer's 2,000 steps cannot nest
   that deep). Not fixed; the size limit now stops any such value whose
   text passes the limit, in both, before either writes it.
