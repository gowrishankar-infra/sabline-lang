# 9.0 M3 - where it stands

The record of M3 (`plan/9.0.md`, *M3 - the interpreter, the budget,
`Secret` and receipts*) as far as it has got, written so that the next
session can pick it up without this one's context. `plan/9.0.md` is the
plan; this file records what was done against it and does not change it.
`plan/9.0-m2-progress.md` is the record of the rung before, and its last
two recommended items were done first here.

**As of 2026-10-08, first checkpoint.** M3 has begun: sabline-rt runs a
program, and the agreement gate compares every run as it compares every
check. It is pre-release **`9.0.0-alpha.6 - M3: ...`**, M3 in progress:
`rt/Cargo.toml` says that version, and release.yml tags it and publishes
the crate when the merge commit's tests pass. Nobody tags by hand.

**M3's exit criteria are not met, and none is claimed.** What is done is
the interpreter's core and every builtin a run under the budget `io` can
reach the work of, held to the reference by the gate over 6,773 runs. What
is not is listed below, in the order to do it.

## What exists now

**In the crate** (`rt/crates/sabline-rt/src/`), each a transliteration of
what it names:

| File | Ports |
|---|---|
| `interp.rs` | `sabline/runtime.py`'s `build_runtime` (`call`, `call_function`, `run`, `eval_`), `run_builtin` for every builtin whose work is pure or the console's, `run_money`, `interpret`; `budget.spend` for every builtin |
| `value.rs` | the Python objects a run holds - `int`, `float`, `str`, `list`, `dict`, `RecordValue`, `MoneyValue`, a function value, `Bound` - and CPython's `==`, ordering, hashing, `str()`, `repr()`, and `values.to_text` |
| `text.rs` | a Text as code points, and `str`'s algorithms: `split`, `in`, `strip`, `upper`, `lower` with the final sigma, `repr`, `isdecimal` |
| `unicode_text.rs` | CPython's `upper`, `lower`, case-ignorable and cased (for the sigma), `isprintable` - generated by `scripts/gen_unicode_text.py` |
| `bigint.rs` | a Python `int` past 64 bits: a literal, or `%` of one |
| `pyjson.rs` | `_json.c`'s scanner, `json.dumps(ensure_ascii=False)`, `int(str)` and `float(str)` |
| `digest.rs` | SHA-256, `bytes.hex`/`fromhex`, base64 (strict, as 3.11+), `urllib.parse.quote` |
| `run_dump.rs` | the canonical run document |

The binary: `sabline-rt run --install-dir DIR --list FILE`.

## Where the port copies CPython rather than Rust

rt/README.md, *What had to be written down to be copied*, has the full
list; the ones that would have been got wrong by reading `runtime.py`
alone:

- **`to_text` and `str()` differ**, and a broken promise's message uses
  `str()`: `True`, `['a', 'b']`, `MoneyValue(units=150, currency='INR')`.
- **A container compares its items by identity first**
  (`PyObject_RichCompareBool`), so a record holding a NaN equals itself.
  The lie corpus holds exactly that case, and it was the one difference
  the first full run of the gate found. Every NaN sabline-rt makes carries
  an identity of its own.
- **`str.lstrip("0")` strips ASCII zeros only**, so `to_int` of twenty
  Arabic-Indic zeros and a one is "too big to hold" - found by the runs'
  corpus.
- **A literal past 64 bits is a value**, and `%` of one can be too.
- **JSON's messages are 3.10-3.12's**; 3.13 words a trailing comma
  differently. **base64 is 3.11+'s strict mode**; 3.10 decoded padding at
  the start of a quad. The gate holds neither, because CPython disagrees
  with itself there.

## What is not done, in the order to do it

1. **The builtins' work for the other budgets**: the file system (the
   guarded paths, `fs` counts, the read ceiling E316, the credential rule
   E318), the clock and randomness (`--freeze-time`, `--seed`: Python's
   `random.Random` is a Mersenne Twister whose `randrange` the port must
   copy), the environment, `declassify` and the two HMACs. Then the run
   document takes a budget, a tree and a seed per program, and the
   conformance corpus's 40 L2 `run` cases and `check_sandbox.py`'s escapes
   run under their own budgets in both. The network, Python (`py`) and
   tools last: each needs a design question answered (*Questions*).
2. **The recorder and `sabline.receipt/1`**, field for field after the
   normalised list in plan/9.0.md; then the audit stream (0007, 32b),
   which is the receipt's fields as they are produced.
3. **A run target for the differential fuzzer** (the plan's
   `fuzz_agreement.py`), once the size question below is answered.
4. **`sabline run` and `sabline.run` through sabline-rt** (decisions/0002),
   which is what lets `check_library.py`, `check_fallible.py`,
   `check_money.py`, `check_hostile.py`, `check_self_budget.py`,
   `check_pool.py` and `check_receipts.py` be asked of sabline-rt.
5. **The organisation ceiling file** (0007, 32c), Python first.
6. **Performance**, which M8 holds to a number: a Text is four bytes a
   code point where CPython keeps one for Latin-1 (PEP 393), and a map
   copied by `put` rebuilds its index. On the gate's programs that grow
   forever - stopped by the step limit - sabline-rt is up to nine times
   slower than the reference; on everything else it is faster.

## Questions for the maintainer

1. **What should a program that grows without bound be stopped by, in a
   run the gate compares?** The step limit stops a program that does not
   end at the same call or loop turn in both runtimes; it does not stop
   one that doubles a text in forty turns, which exhausts memory first,
   and how far either runtime gets before the machine stops it is the
   machine's. One such program is in the gate's corpus today
   (`tests/error_messages/E611_run_memory_cap.vel`), excluded from the
   runs with its reason; a generated program would be the second. The
   choices are a size limit in `run-dump` alongside the step limit (a
   text or list past N items stops the run, in both, at the same
   operation - which adds a check to the reference's `+`), or excluding
   such programs by name as now, or running each comparison under the
   real memory cap (E611) and comparing that it fired rather than where.
   The run target for the fuzzer (*What is not done*, 3) needs the
   answer, because it will write such programs.
2. **How should a function value print?** `print(g)` of a function value
   that carries names writes the Python object -
   `<sabline.runtime.build_runtime.<locals>.Bound object at 0x...>` - and
   one that carries none writes `fn fn#2`; a broken promise naming a
   function-typed parameter writes the AST node's dataclass `repr`. The
   first changes from run to run, so no second runtime can agree with it,
   and none of the three is a Sabline spelling. sabline-rt writes a
   placeholder that differs from all three, so a program that does this
   shows as a difference; none in the corpora does. The record had the
   same defect and was fixed (`RecordValue.__repr__`); a function value
   would want a decision about its spelling, which is the language's.
3. **Should the library-function-value defect be fixed?** A library that
   makes a function value, imported under a name, is refused with "unknown
   function value 'fn#1'" (E402): `qualify` renames the lifted function
   and not the `Closure` that names it. Imported flat, the same library
   compiles. Both runtimes copy it today, which is the gate's job; fixing
   it is a change to the language's behaviour, in both runtimes in one
   commit, and makes `checker.py`'s E402 for a function value unreachable.

## Traps met in this session

- **Bash heredocs halve backslashes**, again, five times: a Rust `'\r'`,
  a JSON test's `\\u12`, a docstring. Write a patch script with the Write
  tool and run it; never put a backslash through a heredoc.
- **The local `python` is 3.13**, whose JSON reader words a trailing comma
  differently from the 3.10 and 3.12 that CI runs the gate on. A
  difference seen only locally may be CPython's, not the port's.
- **`check_gate.py` takes about an hour now**: fourteen injections, each a
  build and a full gate of five comparisons. It runs the live checkout for
  its first ten minutes (the environment check), then works in a copy.
- **A program that grows without bound kills a batch**: sabline-rt
  aborts when an allocation fails, and the whole batch with it. The gate
  says so loudly ("ended ... for the whole batch"), which is safe, and
  `RUN_EXCLUDED` is where such a program goes until question 1 is
  answered.
