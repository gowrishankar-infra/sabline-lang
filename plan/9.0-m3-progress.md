# 9.0 M3 - where it stands

The record of M3 (`plan/9.0.md`, *M3 - the interpreter, the budget,
`Secret` and receipts*) as far as it has got, written so that the next
session can pick it up without this one's context. `plan/9.0.md` is the
plan; this file records what was done against it and does not change it.
`plan/9.0-m2-progress.md` is the record of the rung before.

**As of 2026-10-09, third checkpoint.** sabline-rt records each run's
receipt and audit stream as the reference does, and the agreement gate
compares both, field for field and event for event, for every program it
runs. It is pre-release **`9.0.0-alpha.8 - M3: receipts and the audit
stream, field for field`**: `rt/Cargo.toml` says that version, and
release.yml tags it and publishes the crate when the merge commit's tests
pass. Nobody tags by hand. (alpha.7, the second checkpoint, was published
by release.yml on 2026-10-09: the tag `v9.0.0-alpha.7`, the crate, a
GitHub pre-release.)

**M3's exit criteria are not met, and none is claimed.** What is not done
is listed below, in the order to do it; `sabline run` through sabline-rt is
first.

## The maintainer's decisions of 2026-10-09 (second set), and what was done

The second checkpoint left two questions; the answers are recorded in
`plan/9.0.md`'s M3 section (*Decided on 2026-10-09*, the second block), and
each is done, both runtimes in one commit (`7b17c18` on the branch).

1. **A file that is not UTF-8 text is a failure the program can handle**,
   and writing a text holding a lone surrogate is a failure with nothing
   written. Done: `read_file`/`read_file_secret` fail with `cannot read
   file 'x': it is not UTF-8 text` (`runtime.py`, `interp.rs`);
   `write_file` is not fallible, so its failure is E608 ("the text holds a
   lone surrogate, which is not UTF-8"), and the text is encoded before the
   file is opened - a file that was there is left as it was, a new one is
   not made. SPEC.md 8 says it; the CHANGELOG carries the compatibility
   line. Tests: `tests/unit/test_runtime.py` `FilesThatAreNotUtf8`,
   `tests/runs.rs`, four budgeted runs (`write-a-lone-surrogate-*`,
   `after-a-lone-surrogate`, `read-what-is-not-utf8` reading four kinds).
2. **A library function's broken `requires` names the library's file, and
   the prover's E701 the same.** Done, and wider than asked, because the
   same fault had three more shapes: a broken `ensures` (E601), an error
   raised while a promise is checked (E602 in a `requires`), and the
   program's own promise broken when a library calls it back (which named
   the *library's* file). `call_function` now blames the callee's
   `src_file` for all four (`blamed()` in `interp.rs`). **The prover's
   E701 was already right** - the caller's file, at the call, blamed by the
   caller's function; what printed the importer's name with a library's
   line was `sabline check`'s one-line output, which ignored the error's
   own file (`--json`, SARIF and `run` had it). It prints `err.file` now,
   and `sabline explain` says `line N of lib.vel`. SPEC.md 10 says it.
   Tests: `APromiseNamesItsOwnFile`, `test_prover.py`'s
   `test_check_names_the_file_an_error_is_in`, `runs.rs`, and seven trees
   in `agreement_checks.TREES` (`library-promise-broken-*`,
   `library-calls-back-a-broken-promise`); all seven named the wrong file
   on main.

## What this checkpoint did

1. **The recorder and `sabline.receipt/1`** (`src/receipt.rs`): sites
   (refusal, declassify) once per place with a count, `note_hmac` with
   `key_fingerprint`, `FINGERPRINTS_PER_SITE` and "many", `note_error`
   with `_refusal_effect`'s parsing, the statement with every field and its
   sort orders; subjects via `load_program_recording` (files read, kept on
   a failed load, as Python's `loaded=`), `pypath::relpath` (both flavours,
   Windows' cross-drive `ValueError` as `None`) and the `<stdlib>/NAME`
   rule. The run document writes the receipt after each run; it is the
   command line's receipt of the same run (`test_it_is_what_the_command_
   line_writes` holds the reference's to `sabline --receipt`), with three
   things fixed: confinement `none`, "nothing was asked of the operating
   system"; a step-limit stop recorded as a timeout (E610) and a size-limit
   stop as out of memory (E611); none where the command line writes none.
   The gate's normalisation is `RECEIPT_NORMALISED` and the four
   confinement fields by rule; `check_gate.py` holds that list to
   plan/9.0.md's section (`normalises_only_the_plans_list`).
2. **The audit stream** (decisions/0007, 32b), both runtimes:
   `sabline.audit-stream/1` - `start`, `subjects`, `effect`, `grant`,
   `refusal`, `declassify`, `tool`, `end` with the receipt. Python:
   `_RunRecorder(stream=)` and `tell`, hooks in `budget.spend` and
   `_grant_used`, `receipts.stream_start`/`stream_end`; the CLI's
   `--audit-stream FILE`; `sabline.run`/`Pool.run`/`PoolRegistry.run`'s
   `audit_stream=`, a worker sending `{"audit_event": ...}` messages (not
   `{"audit": ...}`, which is an audit's answer - that collision was made
   and caught here, by check_api.py and check_receipts.py). Rust:
   `Recorder::streaming`, `effect`/`grant`/`tell`, the stream as the run
   document's third record (`sabline.run-batch/3`). `check_library.py`'s
   Secret cases cover the stream (the decision's condition);
   `check_receipts.py` covers the command line; docs/receipts.md says what
   each event holds.
3. **A run target for the differential fuzzer**: `fuzz_parsers.py --target
   agreement_runs` (`RunGen`, `RunAgreementTarget`), on every leg through
   `fuzz_parsers.py 30`, two minutes in the agreement job, twenty in the
   monthly run. It runs both interpreters under `RUN_GIVEN` - every ported
   effect, `fs:read:.,fs:write:.` in a tree made afresh per runtime, a
   frozen clock, a seed, set variables - and its own limits through the run
   document's new `steps` and `size` line options (2,000 and 2^18; the gate
   never gives them). **The residual is respected three ways**: RunGen
   never prints a `List of Text` (the only shape in CheckerGen's grammar
   that serialises one text many times); 2^18 bounds a `push`-built list's
   worst one-operation output at about 73 MB (it is about 4.7 GB under the
   gate's 2^22); and an input that still reaches it (`raised:
   MemoryError` on the reference's side) is counted and printed, never a
   finding. The three CPython-version splits the gate's corpora leave out
   (`reference_split`) are left out the same way, counted. Thirty-five
   minutes of it here found three things: an amount past 64 bits (a real
   difference, fixed in both runtimes - *Found on the way*, 3); its own
   harness normalising a receipt that the stream's `end` shared (fixed:
   compare what was written, re-read); and json's trailing comma under
   CPython 3.13, the first split it now counts. The last ten minutes:
   20,423 runs, no finding, one split.

## What is not done, in the order to do it

1. **`sabline run` and `sabline.run` through sabline-rt** (decisions/0002),
   which is what lets the suites of the fourth criterion be asked of it.
   The run document, receipt and stream are the comparison surfaces it
   needs; what is missing is a command that runs a program for a user.
2. **The network, Python and tools**, each with a design question: the
   network needs a stand-in server in the gate (conform.py's two) and
   `urllib`'s URL parsing, redirects and proxy refusal (E317) copied;
   `py` needs a decision about what a second runtime does with a Python
   host at all; a tool needs the runner's session. A `tool` site in the
   receipt (`tool_calls`, `tool_ceiling`) and the stream's `tool` event
   are Python's only until then.
3. **The organisation ceiling file** (0007, 32c), Python first: named in
   the refusal, the receipt and `sabline audit`, or not shipped.
4. **Performance**, M8's: unchanged from the first checkpoint. The gate's
   run here is 2m25s with receipts and streams.

**A known residual of the size limit**, unchanged: a value is counted when
it is made, so one operation can still write out a value far past the
limit from a container holding one large text many times - and, nested, a
"billion laughs" (each level a two-item list of the one below) reaches any
size in a few dozen short statements. Nothing in the corpora does; the
fuzzer's generator does not write it, its own limit keeps a `push`-built
list's worst case small, and a mutated input that reaches it is counted,
not reported. The gate would fail loudly on one, never quietly.

## Questions for the maintainer

1. **Should the reference stop answering differently by CPython version?**
   Three places, each left out of the gate's corpora and now of the
   fuzzer's comparisons (`fuzz_parsers.reference_split`): json's message
   for a trailing comma (3.13 words it "Illegal trailing comma before end
   of array", a character earlier, where 3.10-3.12 say "Expecting value");
   `int()`'s digit-limit message (3.10 "(4300)", later "(4300 digits)");
   and base64 with leading or excess padding (3.10 decodes it, 3.12 and
   3.13 refuse). sabline-rt copies 3.12. Recommended: the reference says
   one thing on every CPython - 3.12's - in all three, both runtimes in one
   commit, so that neither the gate nor the fuzzer has anything to leave
   out; messages are outside STABILITY.md, and the base64 change refuses on
   3.10 what 3.12 already refuses.
2. **Should the size limit count what a value writes out before writing
   it?** That would close the residual: `to_text`, `print`, `format`, `+`
   and the encoders would count the length of what they are about to make
   (a walk over the value, stopping at the limit) before making it. It is a
   change to what the run document counts, in both runtimes, and would
   move no program the gate holds. Recommended, but not urgent: the fuzzer
   respects the residual as it stands.

## Traps met in this session

- **Bash heredocs halve backslashes** - again, five times. Write patch
  scripts with the Write tool; edit with Edit.
- **A message key that is already an answer.** The pool's worker reads a
  one-key message as an event only for keys that are never an answer;
  `{"audit": ...}` is the answer to an `audit` request. Name a new message
  for what it is (`audit_event`).
- **`_normalised` edits in place.** The gate parses each record from bytes,
  so it never aliases; anything that normalises a receipt it also holds in
  a stream must re-read it from its canonical bytes first.
- **A loop variable in a `finally`.** `run_dump`'s environment restore
  loop used `name`, and moving the receipt's `name` above it named every
  budgeted receipt `SABLINE_GATE_VALUE` - the gate caught it.
- **Module order**: a module before `receipts` in `_MODULES` takes its names
  through `__forward__` and a `TYPE_CHECKING` import (test_pipeline_order).
- **`datetime.fromtimestamp` on Windows** stops at 1969-12-31T12:00Z and
  3001-01-19T21:59:59Z (the C runtime's gmtime); arithmetic does not.
- **CI-like suite runs under load** run several times slower; a ten-minute
  tool timeout is not a failure.
