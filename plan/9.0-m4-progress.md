# 9.0 M4 - where it stands

The record of M4 (`plan/9.0.md`, *M4 - confinement, and a real Windows
AppContainer*) as far as it has got, written so the next session can pick it
up without this one's context. `plan/9.0.md` is the plan; this file records
what was done against it and does not change it. `plan/9.0-m3-progress.md`
is the rung before, which is **done**.

**As of 2026-10-14, fourth checkpoint (`9.0.0-alpha.14`).** **The network's
decisions are sabline-rt's**, which is the half of the port `plan/9.0.md`
gives to M4: the URL is split there, the host and port are matched against
the budget's `net:` grants there, the grant and the operation are counted
there, an ambient proxy is refused there (E317), and every redirect's
target is checked there before it is followed. The socket is sabline-rt's
own for an `http` host and for a request a proxy the budget covers
carries, so the process the operating system holds to the budget's hosts is
the process that opens the connection. The bytes of an `https` exchange are
still the host's - this crate has no TLS stack and takes no dependency for
one - and the receipt says so; M5 finishes it. The maintainer's six answers
of 2026-10-14 are all acted on, one of them differently from how it was
recorded and argued below. On this machine: `check_confine.py` 139/0 and
`--runtime rust` 103/0 on Windows 11; 147/0 and 97/0 on WSL's Ubuntu-22.04
(kernel 6.6, Landlock ABI 3); the agreement gate 41,939/0;
`check_through_rt.py` 325 programs, **0 differences**.

**M4's exit criteria are measured one by one below, and M4 is not declared
done**: criterion 1 is met on two platforms of three, criterion 13's
Windows half is what the maintainer's answer 5 gives to M5, and the
network's port is M4's and M5's together.

### This checkpoint's (`9.0.0-alpha.14`)

- **The network, decided in sabline-rt** (`rt/.../net.rs`, 900 lines with
  its tests; `interp::NET_BUILTINS`). `fetch`, `post`, `fetch_status` and
  `request` are answered there now:
  - **the URL**, split as CPython's `urlsplit` splits one, with the
    scheme, the host lower-cased and its trailing dot gone, the port the
    scheme's own where the URL names none, a bracketed IPv6 address, the
    user information dropped, and a port that is not a number or is out
    of range as the `ValueError` CPython raises - in its words, because
    `host_refusal` repeats them.
  - **the budget's hosts**: `host_refusal` and the `*.` rule, the grant
    counted under the text the budget wrote, and E314 with the package's
    message.
  - **the counts**: one request is one `net` operation whatever its
    redirects, E315 past it with the package's message.
  - **the proxy**: the environment's `http_proxy`/`HTTP_PROXY` read as
    CPython's `getproxies_environment` reads them, `NO_PROXY` honoured,
    `REQUEST_METHOD` making the upper-case name a CGI header; a proxy
    the budget does not cover is **E317 at line 0**, as
    `sabline/budget.py` raises it, and one it covers carries the request
    - the absolute-form request line for `http`, and a `CONNECT` tunnel
    the host makes for `https`.
  - **every redirect's target**, checked against the grants before it is
    followed, with urllib's own rules for what a redirect is and which
    method follows it; a target the grants refuse is the failure a
    program can handle, recorded as `_note_redirect` records it.
  - **the socket**, for `http`: opened in this process, so the Windows
    AppContainer's `internetClient` capability, the Linux seccomp filter
    and the macOS profile are what bound a program's own request. HTTP/1.1
    written in-crate, `Content-Length` and `Transfer-Encoding: chunked`
    both read, the body cut at a megabyte where `resp.read(1 << 20)` cuts
    it, and the ten-second patience urllib is given.
  - **`request`'s document**, `json.dumps({"status", "body", "headers"},
    ensure_ascii=False)` with the headers in the order the response
    carried them and a repeated header keeping its first place and its
    last value, which is what the Python runtime's dict comprehension
    does.
- **What is still the host's, and says so**: the bytes of one `https`
  exchange (`NET_EXCHANGE`, `sabline.net-exchange/1`). It is a transport
  and nothing else - one request, one response, no redirect followed, no
  grant read, nothing counted - made with `http.client` and not
  `urllib.request` for exactly that reason. `confine::relayed_elsewhere`
  says "the bytes of a request to an https host" now, and adds that a
  request to an `http` host is made here and that which host a request may
  reach is this runtime's whatever the scheme.
- **`runtime_reads` under a `net` grant** (`confine_linux.rs`). A run that
  resolves a name needs what glibc's resolver reads - `/etc/hosts`,
  `/etc/resolv.conf`, `/etc/nsswitch.conf` and the rest - **and the
  loader's cache and library directories**, because glibc loads its name
  service modules when it is first asked. Without them `localhost` did not
  resolve and a run was refused a host its budget granted. The Linux leg
  of `check_confine.py` is what found it, on a change whose Windows legs
  were all green. The TLS roots are still not there: this process opens no
  TLS connection.
- **The audit predicts for the runtime that will run** (answer 1).
  `confine.predicted(allow, ...)` is the new entry point, and `sabline
  audit --confinement-probe`, `sabline doctor` and the library's audit use
  it. For the Python runtime it is `predict` as before; for sabline-rt it
  **asks sabline-rt** - `sabline-rt os-policy --predict [--here]`, a
  framed document per budget - rather than modelling its Windows behaviour
  here, which is the second copy `ENFORCES_HELD` was shaped to avoid. The
  crate gains `confine::predict`, `predict_document` and
  `predict_here_document`; `sabline doctor` takes the layer list from the
  same answer, so a level from one runtime is never printed beside the
  layers of another. The audit document's `confinement` gains `runtime`.
  `check_confine.py`'s `rt_predict_cases` holds the two to the same rule
  `ENFORCES_HELD` is held to: over 23 budgets, three systems and both
  modes, no prediction of sabline-rt's is weaker, 19 differ and every one
  is Windows', and Linux and macOS are identical.
- **The receipt wins where they differ, and says so** (answer 1).
  `confine::differs_from_prediction` compares the level the operating
  system gave with what `predict` says for this system, and the receipt's
  reason carries one sentence where they differ. It is asked of what
  `apply` returned, before the note about work outside this process: a
  prediction is of what the kernel will hold, and a call made in another
  process is not the kernel answering differently.
- **The 1,024-file bound is never silent** (answer 3). The receipt named it
  already; the run says it on the error channel too, in the receipt's own
  words, and only for this reason - every other reason a container is left
  off is one the budget asked for. `perf_gates.py --only contained`
  measures what a contained run costs, which nothing did before: on this
  machine a run under `io` is 310 ms against 250 ms with `--no-confine`,
  and an ACE written and taken back is **0.3 ms a file**, so the bound
  costs about a third of a second. The code's and the page's "half a
  millisecond a file" are now that measured number.
- **The memo's key is the Windows build as well as the crate's version**
  (answer 4). `calls::os_build` reads it with `RtlGetVersion` - not
  `GetVersionExW`, which answers 6.2 for a program with no compatibility

  on; a memo from another build says nothing about this one and is
  ignored. `the_os_build_is_this_windows_and_not_a_shimmed_one` holds it.
- **A fault for "the container could not be made"** (answer 6).
  `SABLINE_FAULT_NO_APPCONTAINER`, behind the `fault-inject` feature with
  the no-Landlock fault, makes `outer` fail where `CreateAppContainerProfile`
  would - no ACE written, nothing started - which is the one Windows path

- **A `net` grant with no host leaves the Windows container off** - which

- **A prediction of *this machine* reads what this machine found out.**

## Questions for the maintainer

1. **How should sabline-rt make an `https` request?** It is the last of the
   network, and it is a dependency question rather than a coding one. The
   alternatives are (a) **a TLS crate** - `rustls` with `ring` is about
   fifteen crates transitively, which fits under `plan/9.0.md`'s cap of 25
   but spends nearly all of it, needs a `cargo vet` record each, and ends
   "no dependencies" as a property of this crate; (b) **the operating
   system's own TLS** - Schannel on Windows, Security.framework on macOS,
   and on Linux no library with a stable ABI that is certainly present, so
   `dlopen` of `libssl.so.3` with a fallback, which is three platform
   modules of `unsafe` and a fourth path that is none; (c) **as it is** -
   the bytes of an `https` exchange asked of the host, which decides
   nothing, and the receipt saying so; (d) hand-written TLS, which is not
   an option and is listed so that it is on the record as refused.
   Recommended: **(a)**, with the argument-per-crate discipline
   `plan/9.0.md` asks for, and M7's C ABI as the reason it matters - an
   embedded sabline-rt cannot relay to a Python host. If (a) is refused,
   (c) is honest and M5's exit criteria should say that the `https`
   transport is the host's rather than leaving the port "finished".
2. **Was reversing answer 2 right?** The argument is in *The maintainer's
   six answers* above: (b) ships, (c) is eight lines and a by-design list
   away. It is written as a question because it is your decision that was
   reversed, not because the evidence is thin.
3. **Should the Python runtime's E317 still fire for a proxy only the
   registry names?** `sabline/budget.py` asks CPython's `getproxies()`,
   which reads the environment **and** Internet Settings in the Windows
   registry and the macOS system configuration. sabline-rt reads the
   environment alone - and then opens the socket itself, so there is no
   proxy in the path to bound: its peer is the granted host, which is what
   a `net:` grant is for. So on a machine with a system-wide proxy set
   outside the environment, the Python runtime refuses a run that
   sabline-rt carries out, direct, to the host the budget granted. Neither
   sends anything anywhere the budget does not name. The alternatives are
   (a) as it is, written down in `docs/confinement.md` and in no suite,
   because no runner has such a proxy; (b) sabline-rt reads the registry
   and the system configuration too, which is two more platform modules
   for a refusal it does not need; (c) the Python runtime stops reading
   them, which changes a 8.0 refusal on a machine nobody can test.
   Recommended: (a), and a `docs/known-open.md` row if you would rather it
   were counted.
4. **Should `check_rt.py` hold a list of the environment variables the
   crate reads**, as `check_self_budget.py` holds one for the package? The
   crate now reads `http_proxy`, `HTTP_PROXY`, `https_proxy`,
   `HTTPS_PROXY`, `no_proxy`, `NO_PROXY` and `REQUEST_METHOD` on top of its
   three `SABLINE_` names. `check_self_budget.py`'s C9 and C10 already vary
   the proxy variables through sabline-rt and hold that neither widens what
   a program can do, so the behaviour is covered; what is not is the list
   itself. Recommended: yes, one scan, next session - it is the same
   argument that made the package's list worth having.

## Traps met in this session

- **CI is a platform too.** The Windows leg runs on a Server, where the
  container is left off, and that is the only machine that could have
  found a `doctor` predicting `full` where no run can be full. A claim
  about a machine has to be measured on that machine - and when the
  machine is one nobody has, the way to measure it is to put its answer
  where a test can set it, which is what the memo turned out to be good
  for.
- **A platform's own leg is what finds a platform's own hole.** The port
  was green on Windows in every suite, and the Linux leg of
  `check_confine.py` refused a host the budget granted, because a run that
  resolves a name needs what glibc's resolver reads *and* the loader's
  cache and library directories - which `runtime_reads` did not grant,
  since nothing in this crate had ever opened a socket. Run every
  platform's leg on a change that moves work into the runtime, not only
  the one you are on.
- **A suite that compares two runtimes is where a port's defects live.**
  `check_through_rt.py` found four in the first draft: a refusal raised at
  the wrong line, a body that was not sent and a type that was not named,
  a reason carried where the reference carries none, and a host named `?`
  where the reference names it. Each was a sentence in `sabline/runtime.py`
  read too quickly. **Read the branch, not the function**: `fetch` and
  `request` differ in what they say about the same failure.
- **A decision that was right before a port can be wrong after it.**
  Question 2's recommendation was made while the connection was still the
  host's, and the port is what made it measurable. The thing that settled
  it was not an opinion but the rule the rest of the module already
  followed, and a suite with no way to record a difference by design.
- **An underflow in a count is a crash in release.** The crate is built
  with `overflow-checks = true`, so `net_count -= 1` on a counter that had
  not been incremented aborted the run with a panic rather than wrapping.
  The fix was to stop subtracting at all - the order the reference counts
  in is the order to count in.
- **The heredoc backslash trap caught me again**, in the same shape the
  last session recorded: `"\\n"` inside `python - <<'PY'` arrives as a real
  newline and broke a Python string in `check_confine.py`. And a
  multi-replacement script that asserts at the end writes **nothing** when
  an earlier assertion fails - which silently dropped a change to
  `net.rs` and left a request going to the origin rather than the proxy it
  was given. **Write a file with Write, or an edit with Edit, when the text
  holds a backslash; and never put several asserted replacements before one
  write.**
- **A Windows build will not relink while a stray `sabline-rt.exe` runs**,
  which the agreement gate's own processes are: `cargo build` says *Access
  is denied* on the binary. It is the old trap and it still costs a minute.
- The earlier traps stand: a notice on stderr is a difference in every
  suite that compares it; one folder for both runtimes, remade for each;
  read a failure's message before believing the claim it is about;
  `cargo test` without the feature replaces the binary the suites use; a
  new page under `docs/` cannot be dated until it is committed.
