## Where the port copies CPython rather than Rust

From #144: `infer` re-run where the reference re-runs it; the lifted
function counter across one load; `qualify` skipping `name` fields; paths
joined the way `os.path` joins them; `str.strip()` taking U+001C-U+001F;
float `repr`.

From this PR, for the budget:

- **`os.path.realpath`'s walk** (`pypath::nt::realpath`,
  `pypath::posix::realpath`, each over a `Disk` trait and tested against
  answers CPython gave over the same fake disk). One known divergence: an
  error code outside `ntpath`'s list of "stop here" codes makes CPython
  raise, and the port carries on as for any other.
- **`ntpath.normcase` is `LCMapStringEx`** on CPython 3.13 Windows: one
  character for one, no final sigma. Safe Rust cannot call it; the port
  lowers one character for one, and differs on about 420 letters Windows'
  older table does not lower. No budget in the gate holds one.
- **`str.isdigit()`**, generated (`src/unicode_digit.rs`).
- **`int()`'s 4,300-digit limit**, whose `ValueError` text is the refusal.

Not in the budgets' corpus on purpose, because CPython itself differs
between versions or Windows builds: a path past 260 characters, a NUL in a
path, a loop of links, a letter in that set of 420.

## Traps met in this session

- **Bash heredocs halve backslashes**, here three more times: a Rust
  `"\n"` became a newline, a `'\r'` a carriage return, a line continuation
  vanished. Write patch scripts with the Write tool, or use Edit; in a
  `python -c`, spell a backslash `chr(92)`.
- **`/c/...` paths handed to Python on Windows** resolve against the
  current drive (`D:\c\...`); use `cygpath -w`.
- **`check_gate.py` runs the gate in the live checkout at its start**, so
  an edit to `sabline/*.py` while it runs can make that phase disagree
  with the binary it reads. Let it finish, or rebuild and rerun.
- **A Windows debug build overflows** `json::tests::a_deep_document...`;
  CI tests in release, and so should a local run.
